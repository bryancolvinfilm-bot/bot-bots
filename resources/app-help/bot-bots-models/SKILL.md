# Model servers and context

The model indicator at the top of the app opens **Team model**. **Use for all bots** sets the selected running/connected model and effort for every available bot and its conversation channels once. Individual chats can override it afterward. **Return all to defaults** clears those chat preferences so bots follow their saved profile suggestions. Bot roles, instructions and saved profile defaults remain intact. Archived/deleted bots and retired workers are excluded. Only the owner can change the whole team.

Token counters beside human messages estimate that message's text tokens. Bot replies show the bot's total model usage for that task, with input/output breakdowns when reported. Live counts use streamed text/function arguments and numeric reasoning counts, then reconcile to provider usage. A `~` marks estimates; some services report exact counts only at completion. Cached input is included where the provider reports it. Tool rounds, model switches and context compaction count toward that reply; teammate work is counted on the teammate's reply. These are token counts, not billing estimates. Reasoning text is never displayed or saved by the counters.

Every chat composer has **Model** and **Effort** dropdowns, including when one model is running. The model menu groups connected **Online · frontier models** first, then a divider and **Local · running models**. Unloaded local models, offline entries and embeddings are hidden. Choose across services directly in chat; **Refresh running models** updates the list. Chat preferences are saved for this bot's channel in the current team conversation, without rewriting its profile or other conversations. Choosing a model resets effort to Default. Profile/default model settings are starting suggestions, and automatic failover can use other eligible models. Changing an active chat's selection preserves completed tool results while continuing on the new model. Selecting an online model is the owner's explicit inference opt-in. An operator can use already-enabled models under the current local-only policy.

**Frontier models** connects the whole team to online models. **Continue with ChatGPT** opens browser authorization for an eligible plan. **Continue with Claude** runs the official, unmodified Claude Code tool and its own browser login on the host computer; that tool keeps its credentials. Existing Claude Code login is recognized. First use downloads and checksum-verifies the executable. API keys remain an alternative. Local models can stay enabled, and each bot can choose a service/model. Each bot retains its instructions, duties and normal tool approvals. Do not collect Claude subscription tokens or use a copied token to call Anthropic's API directly.

Open **Model workshop**. **Add a model server** accepts OpenAI-compatible endpoints on this computer or another machine. For local LM Studio use `http://127.0.0.1:1234/v1`; a LAN server uses that machine's IP/hostname and exposed port. In a client session, `127.0.0.1` means the **Bot-Bots server's computer**, not the viewing phone. The other model server must listen on its network interface and be reachable from the host.

**Auto · follow loaded local models** checks enabled local servers every 15 seconds and before model requests. It discovers currently loaded instances and uses the actual loaded context rather than a 32K placeholder or the model's theoretical maximum. Legacy entries without an explicit manual context cap follow the server. The app does not load/unload model weights. Explicit selection of a running model in chat can enable it without visiting Model workshop. Embedding models are not chat models.

For ordinary use leave the bot's model choice automatic. A bot pin or manual global model selection is an explicit owner choice. A server can expose multiple models. Fallback tries other eligible enabled models when a provider/model is unavailable; it respects local-only mode, explicit disables, capabilities and routing preferences. With no eligible models, the app records the outage and configured email/SMS alert channels can warn the owner. Those channels need their own working endpoint/destination/auth setup; don't claim they are connected by default.

**Local-only mode** controls inference, not public browser research. Cloud providers/models require the owner's opt-in. For authentication load `bot-bots-api-tokens`; normal setup connects privately without manual binding IDs. ChatGPT shows saved accounts, Sign out, and a usage-limits link. If a plan is not eligible or sharing is disabled, report the actual connection error; do not claim every subscription automatically grants access.

The next-reply model label follows the currently selected/loaded model. An old reply's model label remains historical. If a switch seems stale, refresh the server, check Auto/manual selection and any bot pin, and verify which models LM Studio actually has loaded. Never report that weights were changed by this chat unless an available tool actually did it.

Input context and output length are different. Increasing loaded context in LM Studio gives room for instructions/history/tools, but does not remove the per-response output limit. For context exhaustion try a larger **loaded** context, a shorter task/new conversation, or deliberate memory/history compaction. Such task limits do not automatically mean the model server is offline.

Online inference has **no Bot-Bots input cap by default**. Claude, ChatGPT and other connected online providers enforce their own capacity. **Model workshop → click the model → Context window → Auto · provider managed (no app cap)** is the default; **Manual context cap** is optional. Reasoning effort is separate from input capacity. Known service windows are used as soft monitoring information, not an artificial preflight rejection.

Automatic working-context compaction watches estimated input size. Near 80% of a known loaded/service window, it summarizes older conversation/tool records and continues the same task. If a provider reports its context is full, the app compacts and retries within the existing task. Current runtime instructions, the current human request and live steering stay intact. Visible messages are not deleted. Compressed local checkpoints retain exact older records and actual error/action states; `context_read` retrieves bounded sections when needed. History summaries can carry into later turns. The chat shows approximate context usage and compaction count. Compaction is background data, never a new human instruction or approval, and completed external actions must not be repeated.

Long code can use Bot-Bots' saved draft notebook: write chunks, inspect checkpoints, continue an unfinished draft, then finish and preview it. Truncated output can continue on the same healthy model within bounded attempts; the system preserves unfinished text instead of pretending it is a completed app. Load `bot-bots-tools` for that workflow.

Human ratings are the strongest quality signal for eligible models/bots. Default relaxed urgency allows slower local models. Explicit urgent work can favor measured faster models among similarly rated choices; successful tasks are not invented star ratings.
